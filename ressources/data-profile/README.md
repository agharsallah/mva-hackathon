# Data profile — committable summaries of the gated dataset

Generated by [`tools/profile-genomic-data.sh`](../../tools/profile-genomic-data.sh).

Everything in this directory is **file shape and aggregate statistics**: headers, contig
lists, field inventories, counts. No variant record and no read sequence is present, so
this directory can live in git while the underlying 85 GB cannot.

Run it as:

```bash
tools/profile-genomic-data.sh ~/mva-data/raw
```

The script writes patient-sequence artifacts (panel VCF extract, FASTQ smoke sample) to
`~/mva-data/work/` instead — outside the repo, covered by the `.gitignore` guard, and
subject to the 30-day deletion obligation.

## What lands here

| File | Contents | Expected size | Cost to produce |
|---|---|---|---|
| `manifest.tsv` | filename, byte size, SHA-256 of first 1 MB per file | < 2 KB | seconds |
| `vcf_header.txt` | full VCF header, sample column renamed to `PROBAND01` | 5–250 KB (depends on contig count) | seconds |
| `vcf_key_facts.txt` | reference build, caller, sample count, chromosome naming | < 3 KB | seconds |
| `vcf_fields.tsv` | every INFO / FORMAT / FILTER field with its description | 3–10 KB | seconds |
| `vcf_contig_counts.tsv` | variants per contig, read from the `.tbi` | < 2 KB | seconds |
| `vcf_stats.txt` | `bcftools stats`: SNP/indel counts, ts/tv, quality and depth distributions | 50–200 KB | 2–5 min |
| `vcf_filter_gt_counts.tsv` | FILTER tallies, genotype tallies, phased-record count | < 2 KB | 3–8 min (one full pass) |
| `fastq_profile.tsv` | per-file read length, estimated read count, estimated Gbases, plus a coverage rollup | < 2 KB | ~10 s per file |
| `fastq_read_headers.tsv` | first read name per file, index barcode redacted | < 2 KB | seconds |
| `mva_panel_grch38.bed` | MVA candidate genes + rhabdomyosarcoma differentials, GRCh38, 20 kb padding, fetched from Ensembl | < 1 KB | seconds (needs network) |
| `panel_variant_counts.tsv` | variant count per panel gene — a count, not a record | < 1 KB | 1–2 min |

**Total committed: roughly 100–500 KB.** Under a megabyte for a complete picture of an
85 GB dataset.

## What each artifact is actually for

**`vcf_key_facts.txt` is the highest-value file in the directory.** Three lines in it
decide the entire plan:

- *reference build* — must be GRCh38 or every submitted coordinate is wrong.
- *sample count* — 1 means single proband and no free phasing; 3 means a trio and the
  compound-het question answers itself.
- *caller* — GATK, DeepVariant and dragen have different blind spots, and the second
  allele is most likely hiding in whichever one this pipeline has.

**`vcf_fields.tsv`** tells us what annotation already exists. If the organizers' pipeline
already ran VEP or attached gnomAD frequencies, we skip a slow step. If `DP`/`AD` are
present we can look for allele-balance outliers, which is how a mosaic or low-quality
true call betrays itself.

**`vcf_filter_gt_counts.tsv`** is the cheap route to the hard second allele. If a large
number of records carry a non-`PASS` FILTER, the missing variant may already be in the
file, just suppressed. Checking that costs minutes; re-calling from FASTQ costs a day.

**`fastq_profile.tsv`** gives real depth instead of the assumed 30×. Read count is
estimated by decompressing a 200 MB slice of each file and scaling by compressed size —
accurate to a few percent, and it takes seconds rather than the ~30 minutes a full
`wc -l` over 85 GB would need. Depth determines whether calling a heterozygous deep
intronic variant is realistic.

**`panel_variant_counts.tsv`** is the first real signal. A gene with an unusually high
or low count relative to its length is worth a look, and a zero count in `BUB1B` would
be a strong hint that the answer is a structural variant the caller never emitted.

## What deliberately does not land here

| Artifact | Where it goes | Why not here |
|---|---|---|
| `panel_mva.vcf.gz` — the actual variants in the candidate genes | `~/mva-data/work/` | real patient genotypes |
| `*.100k.fastq.gz` — 100k-read smoke sample for pipeline development | `~/mva-data/work/smoke/` | real patient sequence |
| Any BAM, any IGV screenshot, any variant table with coordinates from the patient | nowhere near git | DTA violation |

The smoke sample is worth calling out as a working practice: develop and debug the whole
align → call → annotate → rank → emit-CSV chain against 100k reads, where a full run takes
seconds, and only then point the finished pipeline at the real 85 GB. It also makes the
"runtime and cost" answer on the methods form something we measured rather than guessed.
