# Data profile — committable summaries of the gated dataset

**Standing:** the raw evidence behind
[`ideation/data-findings.md`](../../ideation/data-findings.md), which owns the numbers.
File list checked against the directory 2026-08-29.

Generated by [`tools/profile-genomic-data.sh`](../../tools/profile-genomic-data.sh).
Interpretation lives in [`ideation/data-findings.md`](../../ideation/data-findings.md);
this directory is the raw evidence behind it.

Everything here is **file shape and aggregate statistics**: headers, contig lists, field
inventories, counts, distributions. No variant record and no read sequence is present, so
this directory can live in git while the underlying 80 GB cannot.

```bash
tools/setup-env.sh                              # once
source tools/activate.sh
tools/profile-genomic-data.sh ~/ubuntu/data     # ~10 min, mostly one full VCF pass
```

Patient-derived artifacts (panel VCF extract, FASTQ smoke sample) are ingested into the
warehouse database instead — outside the repo, queried through the reads API / viz API,
and subject to the 30-day deletion obligation.

## What lands here

| File | Contents | Cost |
|---|---|---|
| `manifest.tsv` | filename, byte size, SHA-256 of first 1 MB per file | seconds |
| `vcf_header.txt` | full VCF header; sample column, lab accession and provider job paths redacted | seconds |
| `vcf_fields.tsv` | every INFO / FORMAT / FILTER field with its description | seconds |
| `vcf_contig_counts.tsv` | records per contig, from the index | seconds |
| `vcf_stats_summary.txt` | `bcftools stats` aggregates: SNP/indel counts, ts/tv, indel length, substitution types | 2–5 min |
| `vcf_filter_gt_counts.tsv` | FILTER tallies, genotype tallies, records carrying physical phasing | 3–8 min |
| `vcf_chrom_allele_balance.tsv` | per-chromosome het VAF and depth — the mosaic aneuploidy fingerprint | 3–8 min |
| `fastq_profile.tsv` | per-file read length, estimated reads and Gbases, plus a coverage rollup | ~10 s per file |
| `fastq_read_headers.tsv` | first read name per file, index barcode redacted | seconds |
| `fastq_qc_L001.tsv` | Q30, GC, duplication, insert size from 500k read pairs | ~10 s |
| `mva_panel_grch38.bed` | MVA genes + rhabdomyosarcoma differentials, GRCh38, 20 kb padding, from Ensembl | seconds, needs network |
| `panel_variant_counts.tsv` | variant count per panel gene — a count, not a record | 1–2 min |
| `hf_lfs_sha256.tsv` | the publisher's own SHA-256 per delivered file, read from the dataset's Git-LFS pointers | seconds, needs network |

Roughly 600 KB for a complete picture of an 80 GB dataset.

`hf_lfs_sha256.tsv` is load-bearing rather than descriptive: it is what
`mva-warehouse source-check` compares uploaded objects against, so it is the reason
"hash-verified" means *verified against the publisher* and not merely *self-consistent*.
Added by [`methodology/014`](../../docs/step-0/methodology/014-source-of-truth-and-lineage.md).

## Redaction

`vcf_header.txt` is not a verbatim copy. The delivered header carries the lab accession
(`WGS_EX…`) in the sample column *and* inside the Sentieon and GATK command lines, along
with the sequencing provider's internal DNAnexus job paths. The script rewrites the
accession to `PROBAND01` and collapses those paths before the header reaches the repo.
If you regenerate by hand, do the same.

## What deliberately does not land here

| Artifact | Where it goes | Why not here |
|---|---|---|
| `panel/panel_mva.vcf.gz` — the actual variants in the candidate genes | warehouse DB, via the reads/viz API | real patient genotypes |
| `smoke/smoke_200k_R{1,2}.fastq.gz` — pipeline smoke sample | warehouse DB, via the reads/viz API | real patient sequence |
| Any BAM, any IGV screenshot, any variant table with patient coordinates | nowhere near git | breaks [the rule](../../docs/notes/no-patient-data-in-the-repository.md) |

Synthetic stand-ins for the smoke sample live in [`tests/fixtures/`](../../tests/fixtures/)
and are safe to commit, read and share.
