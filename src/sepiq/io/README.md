# `io/` — format parsers, below every domain layer

**Standing:** 2026-10-05 — verified against the source on this branch.

These read the plain-text shapes command-line tools emit and know nothing about one
dataset or one challenge. They know about **shapes**, not meanings. Everything
case-specific is assembled a layer up.

That split is what makes the toolkit transfer: pointing it at a different dataset means
writing a new assembly layer, not a new parser.

## Modules

| Module | Holds |
|---|---|
| `readers.py` | `read_table()` — a header-first TSV; `read_sections()` — a file cut into `## name` blocks; `as_int()` / `as_float()` — tolerant coercion. The shapes they return are `Table` and `Sections`. |
| `writers.py` | `write_tsv()`, `write_json()`, `cell()` — staging a step's rows and numbers to disk in a form a loader can read back. |

## Two conventions, shared by everything here

- **A missing value is `None`, never an exception.** These files are generated by shell
  pipelines, and a truncated run must degrade to a gap in a chart rather than a crash
  halfway through a report.
- **Nothing is coerced on read.** Values arrive as strings and become numbers only where a
  caller asks for a number, because a column that is an integer in one dataset is a float
  or a sentinel in the next. (The SEPIQ dataset's `-500` is exactly that case.)

## The two shapes, by example

`read_table()` handles the thing real tools emit: a proper table, with two-field rollup
lines glued underneath it and `#` provenance comments on top.

```text
# generated by some-tool v1.2 --window 50
name      count   mean
alpha     1200    0.41
beta       870    0.38
est_total_x       2070
```

```text
t = read_table("summary.tsv")
t.columns          # ('name', 'count', 'mean')
t.rows             # [{'name': 'alpha', 'count': '1200', ...}, ...]
t.scalars          # {'est_total_x': '2070'}   <- NOT a malformed row
t.comments         # ['generated by some-tool v1.2 --window 50']
t.column("count")  # ['1200', '870']
```

The `scalars` split is the point. Without it the rollup line arrives as a ragged record
and either raises or silently becomes a row with two empty cells — both worse than a
separate mapping.

`read_sections()` handles the other common shape: one file holding several unrelated
blocks.

```text
## totals	2070
## by_group
alpha	1200
beta	870
```

```text
s = read_sections("report.txt")
s.scalars           # {'totals': '2070'}
s.blocks            # {'by_group': [('alpha', '1200'), ('beta', '870')]}
s.counts("by_group")  # {'alpha': 1200, 'beta': 870}  <- non-integers dropped
```

## Callers

Nothing yet on this branch, by design: `io` is a leaf and the layer that would sit on it
is the not-yet-written data-ingest code. It imports no sibling package and nothing imports
it, which is checked by the "leaf packages import no sibling package" contract in
`pyproject.toml`.
