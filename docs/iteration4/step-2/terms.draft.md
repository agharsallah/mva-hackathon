**Inference tier** — what it costs to get one model's opinion, in three steps: tier 1 = look the
answer up in a table somebody else already computed, tier 2 = run the model here on the laptop's
CPU, tier 3 = run it on a rented GPU. The tier is a property of *how we reach* the model, not of
how good it is.
*Example:* AlphaMissense is tier 1 in this repo (its scores are already a warehouse column),
ESM2 650M is tier 2 (hours of laptop CPU), Evo 2 is tier 3 (an H100 on Modal).
*Context: the `tier` field of every model card, and the reason the MVP roster is four tier-1
lanes · source: `src/mva/zoo/models.toml`, `src/mva/zoo/types.py` (`Tier`) · related: model
card, precomputed scores, zero-shot inference · first seen 2026-09-18*

**Precomputed scores** — a published file in which somebody has already run a model over *every*
variant it can speak about, so using the model means a table join rather than an inference run.
The software-engineering analogy is a materialised view: the expensive query ran once, at the
publisher's expense, and everyone downstream does a lookup.
*Example:* Brandes 2023 published ESM1b's effect for all ~450 million missense changes over
42,336 human protein isoforms as a 1.24 GiB zip (`ALL_hum_isoforms_ESM1b_LLR.zip`); scoring our
callset against it is a join on protein accession plus protein change, not a GPU job.
*Context: what makes the MVP runnable on a laptop in a day · source: `docs/iteration4/plan.md`
§5 step 2, `tools/fetch_zoo_tables.py` · related: inference tier, model card · first seen
2026-09-18*

**Model card** — the README of one model: its name, the exact published version scored against,
where its numbers come from, what its licence allows, whether it has seen variant catalogues,
and — after a run — how much of our data it could actually speak about. In this repo a card is
generated from a registry entry, never hand-written, so a model cannot be used without one.
*Example:* `docs/iteration4/cards/revel.json` — tier 1, source `vep-rest`, plugin flag `REVEL`,
non-commercial, catalogue-adjacent, PMID 27666373, enabled.
*Context: the reusable half of step 2; generated by `mva.zoo.registry.write_cards()` from
`src/mva/zoo/models.toml` · source: `docs/iteration4/cards/README.md` · related: inference tier,
catalogue-adjacent, non-commercial licence, Coverage · first seen 2026-09-18*

**Non-commercial licence** — terms that allow research or academic use but forbid commercial use
(and usually redistribution of the file). It is a constraint on what the repository may *ship*,
not on what the hackathon may *run*: hackathon use is non-commercial.
*Example:* AlphaMissense is CC BY-NC-SA 4.0 and SpliceAI's precomputed scores are under
Illumina's non-commercial terms, so this repo commits the fetch script and the file's sha256
digest and never the score file itself.
*Context: the `non_commercial` column of `docs/iteration4/cards/licences.md`, generated from the
registry · source: `src/mva/zoo/registry.py` (`SHIPS`) · related: model card, provenance
manifest · first seen 2026-09-18*

**Catalogue-adjacent** — said of a model that was trained on a variant catalogue (ClinVar, HGMD
and friends), so it may have *memorised* the answer for a variant that is already catalogued
rather than predicted it. Not a disqualification — a flag, because such a model cannot be
counted as an independent opinion about a known variant.
*Example:* REVEL is an ensemble trained on catalogued pathogenic/benign labels and is flagged
`catalogue_adjacent = true`; AlphaMissense, SpliceAI and ESM1b are not. Step 6 therefore prints
the merged ranking twice — with and without the adjacent lanes.
*Context: the ablation the plan never cuts (plan D4) · source: `docs/iteration4/plan.md` §5 step
2 · related: model card, circularity, Reciprocal Rank Fusion · first seen 2026-09-18*

**Protein language model (pLM)** — a model trained only to predict amino acids in protein
sequences, the way a text language model predicts words. Having read millions of natural
proteins, it finds a substitution "surprising" exactly where evolution rarely allows one, and
that surprise is used as a damage score. It never saw a clinical label.
*Example:* ESM1b (Brandes 2023) reports a log-likelihood ratio per substitution — at most 0, and
the more negative the more surprising — so the adapter negates it to keep the zoo's convention
that a higher score means more damaging.
*Context: the ESM1b, ESM2 and ESM-C lanes of the roster · source: `src/mva/zoo/models.toml`
(`[models.esm1b]`), PMID 37563329 · related: zero-shot inference, catalogue-adjacent, DNA
language model · first seen 2026-09-18*

**DNA language model** — the same idea one level down: a model trained to predict DNA bases
rather than amino acids, so it can score *any* variant — non-coding, synonymous, splice-region —
not only those that change a protein.
*Example:* GPN-MSA publishes precomputed scores for all ~9 billion possible single-base changes
in GRCh38 (tier 1, no GPU); Evo 2 and Nucleotide Transformer v2 are the tier-3, GPU versions of
the same idea.
*Context: the widest-coverage lanes on the roster, all optional in the MVP · source:
`src/mva/zoo/models.toml` (`[models.gpnmsa]`, `[models.evo2]`, `[models.ntv2]`), PMIDs 39747647,
39609566 · related: protein language model, zero-shot inference, inference tier · first seen
2026-09-18*

**Zero-shot inference** — using a model for a task it was never trained on, with no labelled
examples and no fine-tuning: the score is read straight out of what the model already learned.
The opposite of a supervised predictor, which was shown labelled pathogenic and benign variants.
*Example:* asking a protein language model how surprising an amino-acid substitution is, and
calling that surprise a pathogenicity score, is zero-shot; REVEL, trained on catalogued labels,
is not.
*Context: why pLM and DNA-LM lanes are independent evidence and REVEL is flagged · source:
`docs/iteration4/plan.md` §5 step 2 · related: protein language model, DNA language model,
catalogue-adjacent · first seen 2026-09-18*
